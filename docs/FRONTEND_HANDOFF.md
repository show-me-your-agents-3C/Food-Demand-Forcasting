# 本地网页演示交接

本工作副本基于队友的 `feat/backend-agent-api` 下载快照；下载原文件未改动。

## 启动

在 macOS 中双击项目根目录 `start-local.command`，保持打开的终端窗口运行。
浏览器访问 `http://127.0.0.1:8001`。如果端口已有服务，直接访问已有页面即可。
脚本优先使用项目 `.venv`，其次使用之前验证时的临时环境；两者都不存在时寻找 Python 3.10–3.12，创建环境并安装 `requirements.txt`。
系统默认 Python 3.14 不适用于这份依赖。

也可按 README 创建 Python 3.10–3.12 虚拟环境，然后运行：

```bash
python -m uvicorn src.api.main:app --host 127.0.0.1 --port 8001
```

无网关配置时，聊天使用规则备用模式。接真实模型须填写后端 `.env`；不要把密钥写入前端。

## 本次增加

- 原生 HTML / CSS / JavaScript 中文网页，无需 Node 构建或外部字体、图表 CDN。
- 同源静态页面：FastAPI `/` 返回网页，`/assets` 提供资源，原有 API 保持兼容。
- 门店、品类和建议类型筛选；指标按当前门店/品类计算，WAPE 明确标为全局基线。
- 逐门店品类的预测图，避免将不同品类销量单位混加。点击表格联动图表和聊天上下文。
- CSV 导出包含当前筛选结果和历史/模拟标记；并不生成实际采购订单。
- 聊天建议问题、历史上下文、实际模式、工具参数、数据来源和原始结果。
- 加载、错误、无结果状态；移动端布局和键盘访问。

## 为界面正确联调所做的后端修正

- 将备用回答拆到 `src/api/fallback.py`，支持中文回答，保留门店/品类、拒绝未知门店、继承用户追问上下文。
- 修正风险查询被“有哪些”抢先匹配、需求下降变成上升、百分比被识别成门店、聊天无视天数等问题。
- 修正 WAPE 口径；明确促销百分比是需求假设，销量并非统一的箱数/瓶数。
- dotenv 在路径配置导入之前加载；占位网关不再视为已配置；模型请求设定超时。
- 健康检查核查全部业务结果文件，避免补货文件存在就误报数据完整。

原有预测、补货计算、输出文件和大型数据加工逻辑未改动。原有 7 个工具与 8 个接口保留。

## 演示路径

1. 默认门店 1、全部品类，查看需补货组合数和报废风险数。
2. 选乳制品：7 天预测合计 3961，模拟库存 848.79，计划采购量 3420。
3. 点击“为什么需要补货？”并展开工具依据。
4. 点击“需求增加 20% 会怎样？”：计划采购量由 3420 变为 4220。
5. 切换门店或品类，核对表格、图表和聊天范围同步改变。
6. 按“导出建议”下载当前筛选的 CSV；打开“数据说明”查看假设。
